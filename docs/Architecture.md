# DOU Platform — Architecture

منصة توصيل ولوجستيات (السعودية + مصر). النموذج المؤكد:

> **"مش بننافس منصات التوصيل، بنشغّلها."**
> جزآن متكاملان: بنية تشغيلية (أساطيل) + واجهة نمو (كومرس محلي).

## 1) المنتجات

| # | المنتج | الجهاز | المستخدم |
|---|---|---|---|
| 1 | تطبيق العميل | موبايل (Flutter) | العميل |
| 2 | صفحة/لوحة التاجر | Web + Mobile | التاجر |
| 3 | تطبيق المندوب / الفريلانسر | موبايل (Flutter) | المندوب |
| 4 | DOU Fleet Partners | Web (منصة واحدة) | الشركة اللوجستية + فريق Dou |
| 5 | Admin / FinOps | Web | فريق Dou |

## 2) طبقات النظام

```
الواجهات (Mobile / Web)
        │  REST + WebSocket
API (FastAPI)  ── [Auth] ──> Services
        │                        │
   [Dispatch Engine]      [Billing / Payouts]
        │                        │
   PostgreSQL (SQLite في الـ MVP) + Redis (لاحقاً)
        │
   تكاملات خارجية:
   Maps · Mada/STC Pay · Vodafone Cash
   سمسا SMSA · بوسطه Bosta · أرامكس Aramex
```

## 3) محرك الإرسال الذكي (Dispatch Engine)

القلب — يقرر من يوصّل كل طلب:

```
طلب جديد
  ├─ التاجر "وصل بنفسك" (SELF)؟ ─────→ مندوب التاجر
  ├─ طلب محلي (نفس الحي)؟ ──────────→ ① مناديب الشركات المتاحين
  │                                   ② فريلانسرز (الأفضل: قرب/أداء/توفر)
  └─ طلب بعيد (≥25كم)؟ ─────────────→ شركة شحن عبر API (سمسا/بوسطه/أرامكس)
```

معايير اختيار المندوب: المنطقة/الوردية النشطة، معدل قبول ≥85%، مستندات سارية، حمل حالي <3، مسافة، نقاط الأداء. السائق المخصص (COMPANY) له أولوية على الفريلانسر.

## 4) نموذج البيانات (10 كيانات أساسية)

- `tenants` — شركة لوجستية / كيان (multi-tenant)
- `fleets` — أسطول / مجموعة مناديب + pool على الطلب
- `couriers` — مندوب شركة أو فريلانسر (GPS، توفر، أداء)
- `merchants` — تاجر (مطعم/متجر) + ثيم المتجر
- `products` — كتالوج التاجر
- `orders` — طلب + طريقة التوصيل + الحالة
- `order_items` — بنود الطلب
- `courier_tasks` — مهمة توصيل لدى مندوب

## 5) حالات الطلب

```
DRAFT → PLACED → ACCEPTED → PREPARING → READY → ASSIGNED
      → PICKED_UP → IN_TRANSIT → DELIVERED → COMPLETED
      → CANCELLED / FAILED
```

مهمة المندوب: `OFFERED → ACCEPTED → AT_MERCHANT → PICKED_UP → IN_TRANSIT → DELIVERED`

## 6) التدفق المالي (فصل المسارات)

- العميل → التاجر (ثمن الطلب) + Dou (رسوم التوصيل)
- التاجر → Dou (رسوم منصة 1 ر.س/طلب)
- Dou → المندوب (أجر التوصيلة)
- Dou → شركة الشحن (الشحن الطويل)
- الشركة اللوجستية → Dou (اشتراك SaaS شهري)

## 7) السوقان

| | السعودية 🇸🇦 | مصر 🇪🇬 |
|---|---|---|
| الهدف | 200 شركة لوجستية | 50 ألف فريلانسر |
| المندوب المحلي | مناديب الشركات المتاحين | فريلانسر قريب |
| الشحن البعيد | سمسا/أرامكس API | بوسطه/أرامكس API |
| الربح | اشتراك + 1 ر.س/طلب | رسوم يومية + 1 ج.م/طلب |

## 9) حالة التنفيذ (تم البناء)

### الواجهات المتصلة (كلها بالـ API الحي)

| الواجهة | الرابط | المزايا |
|---|---|---|
| البوابة | `/` | روابط كل المنتجات |
| تطبيق العميل | `/static/customer.html` | اكتشاف تجار، سلة، دفع، **تتبع الطلب + شريط تقدم**، طلباتي |
| لوحة التاجر | `/static/merchant.html` | طلبات + **قبول/جاهز**، منتجات، صفحة متجر، ثيم، طريقة توصيل |
| تطبيق المندوب | `/static/courier.html` | حضور GPS، مهام بقبول/رفض/تسليم، أرباح، تحديث لحظي |
| DOU Fleet Partners | `/static/fleet.html` | نظرة عامة، مناديب، طلبات، ورديات، **أداء، مدفوعات، امتثال، قواعد**، شحن |
| Ops Cloud | `/static/ops.html` | إحصائيات، طلبات، مناديب، **تحليلات + أفضل تجار**، إنشاء طلب |

### الـ Backend
- ✅ المصادقة JWT + أدوار + تسجيل/دخول
- ✅ محرك إرسال ذكي: محلي→مندوب، بعيد→شركة شحن، تاجر "وصل بنفسك"
- ✅ دورة حياة مهمة: رفض→إعادة إسناد→قبول→تسليم
- ✅ ورديات + حضور/انصراف GPS
- ✅ شركات شحن (سمسا/بوسطه/أرامكس) + إنشاء شحنات
- ✅ تحليلات: نظرة عامة، أداء، مدفوعات، امتثال، أفضل تجار
- ✅ **35 endpoint** · توثيق Swagger على /docs
