# تقرير قبول: استيراد المندوبين وتزامن تطبيق المندوب

**النطاق:** تصحيح محدود لقالب استيراد المندوبين، ثم تحقق قبول من المسارات الفعلية لتطبيق المندوب إلى لوحة الشركة والمشرف والتقارير والرواتب. تم تنفيذ العمل محلياً على قواعد SQLite معزولة. لم يُدفع أي تعديل إلى GitHub ولم يُنشر أي إصدار إلى Render.

> لا يغير هذا التسليم نموذج المدينة أو العقد أو الفرع أو المشرف، ولا يضيف قاعدة مالية أو خصم حضور أو مصدر طلبات جديد. بقي `DailyLog` مصدر الطلبات المؤهلة، وبقي محرك الحساب المالي الموحد مصدر البونص والراتب والإيراد والهامش.

## 1. ملخص تنفيذي

تم استبدال قالب الاستيراد المربك بقالب مهني خاص ببيانات المندوب، يدعم UTF-8 مع BOM وCRLF، ويعرض صف اختبار واحداً غير شخصي. أزيل تكرار جوال المشرف من القالب، وأعيدت تسمية أجر المندوب لكل طلب بصورة صريحة، ولم يُضف سعر العميل أو إيراد الشركة أو الهامش إلى ملف استيراد المندوبين.

أثبتت اختبارات القبول أن المندوب المستورد يمر من إنشاء `Courier` و`User` إلى الأداء والبونص والرواتب والتقارير دون عدّ مزدوج، وأن نفس السجل يظهر في نطاق الشركة والمشرف. كما كُشف عيبان فعليان وأصلحا: لم يكن `GET /couriers/me` يعيد IBAN الذي يعدله المندوب، ولم يكن رفع المستند محمياً من المندوب الموقوف. أضيفت تغطية دائمة لكلا الحالتين.

| المجال | النتيجة | الدليل |
|---|---|---|
| قالب استيراد المندوبين | **PASS** | تنزيل UTF-8/BOM، صف اختبار واحد، 15 صفاً صالحاً، اسم عربي، أخطاء صف/حقل/قيمة، تأكيد ذري ومنع إعادة الملف. |
| علاقات المدينة/العقد/الفرع/المشرف | **PASS** | المدينة والعقد والفرع والمشرف تُحل داخل `tenant_id` ثم يثبتها `require_branch_assignment`. |
| DailyLog إلى البونص والراتب | **PASS** | 25 + 30 = 55، ثم 500 = 1,800، ثم 550 = 2,050 في تطبيق المندوب والشركة والمشرف والتقرير وكشف الراتب. |
| منع العدّ المزدوج | **PASS** | إعادة إرسال اليوم نفسه تحدّث سجل `DailyLog` نفسه؛ واستيراد الأداء لذلك اليوم يحل محل القيمة بدلاً من جمعها. |
| لقطة الرواتب المقفلة | **PASS** | بعد الإقفال يقرأ تطبيق المندوب `PAYROLL_SNAPSHOT` ولا تتغير قيمة البونص المقفلة عند تعديل مصدر مفتوح. |
| تزامن وظائف تطبيق المندوب | **PASS** | الملف، الحالة، الوردية، الحضور، المستند، الإجازة، التذكرة، والرد اختبرت ضد المستهلكات الفعلية. |
| عزل الصلاحيات والتعليق | **PASS** | العبث بمعرّف مندوب آخر مرفوض؛ والمندوب الموقوف لا ينفذ إجراءات تشغيل حساسة. |
| ترجمة الوظائف المعدلة | **PASS — تحقق ثابت** | اختبر قاموس الترجمة ومراقب النصوص الديناميكية؛ لم تتوفر جلسة متصفح الرسومية في بيئة الاختبار المحلي. |

## 2. تصحيح قالب استيراد المندوبين

القالب الجديد لا يستورد إلا بيانات تخص المندوب وتعيينه التشغيلي. لا يحمل أية قيمة تخص العميل أو إيراد الشركة أو الهامش أو خطط البونص. يبقى تعديل الأجر الفردي للمندوب ضمن حقول المندوب فقط.

| عمود CSV الحالي | الاستخدام داخل النظام | قاعدة الحل أو التحقق |
|---|---|---|
| `name` | `Courier.name` و`User.name` | مطلوب. |
| `mobile` | `Courier.phone` و`User.phone` | يوحّد تنسيق رقم الجوال ويتحقق من عدم تكراره داخل الملف أو النظام. |
| `initial_password` | حساب دخول المندوب | مطلوب وبحد أدنى 8 أحرف. |
| `national_id_or_iqama` | `Courier.iqama_number` | اختياري؛ لا يضيف نموذج هوية موازياً. |
| `nationality` | `Courier.nationality` | اختياري. |
| `city` | مدينة تشغيل مفعلة للشركة | تحل داخل `TenantOperatingCity`. |
| `branch` | `ContractBranch` | يجب أن يطابق العقد والمدينة ويكون نشطاً. |
| `contract_or_project` | `Contract` القائم | يحل بالاسم ضمن الشركة؛ المشروع يشتق من الفرع المعتمد. |
| `supervisor` | `User` بدور مشرف | الاسم المسجل الكامل مطلوب ويجب أن يكون فريداً ونشطاً ضمن الشركة. |
| `base_salary` | تعويض المندوب | رقم غير سالب؛ ليس سعراً تجارياً. |
| `employment_status` | حالة توظيف المندوب | `ACTIVE` أو `SUSPENDED`. |
| `rider_rate_per_order` | `Courier.per_delivery_rate` | أجر المندوب لكل طلب فقط، وليس سعر العميل. |
| `vehicle_type` و`vehicle_plate` | بيانات المركبة | اختيارية. |

التوافق الخلفي محدود ومقصود: تقبل المعاينة رؤوس القوالب القديمة مثل `phone` و`contract` و`status` و`per_delivery_rate` وتحوّلها داخلياً إلى الأسماء الجديدة، لكن ملف التنزيل الجديد لا يعرضها. هذا يمنع تعطل ملف متبقٍ لدى شركة من دون إبقاء تصميم القالب الملتبس.

## 3. سلسلة المصدر الواحد ومنع العدّ المزدوج

```text
CSV المندوب → معاينة علاقات الشركة → OperationalImportBatch(PREVIEW)
→ تأكيد ذري → Courier + User

تطبيق المندوب أو CSV الأداء → DailyLog واحد لكل مندوب/مشروع/تاريخ
→ محرك البونص الموحد → calculate_payroll_preview
→ تقارير الشركة/المشرف/الفرع → PayrollSnapshot بعد الإقفال
```

يحل الاستيراد اسم المدينة والعقد والفرع والمشرف قبل الحفظ، ثم يعيد `require_branch_assignment` اختبار الربط في طبقة الخدمة. لا ينشئ وضع المعاينة سجلات مندوبيّن. يحتفظ `OperationalImportBatch` ببصمة الملف، ولا يسمح بتأكيد الملف نفسه مرة ثانية. أخطاء المعاينة تعيد رقم الصف والحقل والقيمة المدخلة وسبب الرفض، لذلك يمكن للمستخدم تصحيح الملف قبل التأكيد.

## 4. تدقيق وظائف تطبيق المندوب وتزامنها

| وظيفة التطبيق | الكتابة أو القراءة المعتمدة | ما اختبر بعد الإجراء |
|---|---|---|
| تعديل الاسم وIBAN | `PATCH /couriers/me` إلى `Courier` و`User` | `GET /couriers/me` وملف الشركة وملف المشرف تظهر القيم ذاتها. |
| متصل/غير متصل | `POST /couriers/{id}/online|offline` | `Courier.is_online` ظاهر للشركة والمشرف. |
| ورديتي | `GET /shifts/me` | الوردية التي ينشئها حساب الشركة تظهر للمندوب المعيّن. |
| حضور وانصراف | `/shifts/attendance/check-in|check-out` | سجل حضور واحد للمحاولة المكررة، ثم نفس السجل للشركة والمشرف. |
| المستندات | `POST /hr/me/documents` | المستند نفسه يظهر في قائمة المندوب والشركة والمشرف. |
| الإجازة | `POST /hr/me/leave` | الطلب مرئي للشركة والمشرف؛ اعتماد المشرف ثم الشركة يعود للحالة الصحيحة للمندوب. |
| تذكرة الدعم | `POST /couriers/me/tickets` | تذكرة مربوطة بالمندوب من JWT، ورد الشركة يعود إلى قائمة المندوب. |
| سجل الأداء والمستحق | `/hr/me/log` و`/hr/me/logs` | يمر إلى التقرير اليومي وتقرير البونص وكشف الراتب والمالية، ويقرأ لقطة مقفلة بعد الإقفال. |

## 6. قبول الأداء والبونص والرواتب

اختبار `test_rider_performance_acceptance.py` أنشأ عقداً تجارياً بمعدل عميل 10، ثم فرعاً وخطة بونص سارية من أول الشهر: تارجت 500، مكافأة 1,800، و5 لكل طلب زائد. أُنشئ المندوب عن طريق قالب الاستيراد الجديد، ثم سُجلت عملياً القيم التالية.

| الخطوة | DailyLog الشهري | البونص المتوقع | ما تحقق |
|---|---:|---:|---|
| اليوم الأول: 25 | 25 | 0 | تطبيق المندوب، ملف الشركة، وملف المشرف متطابقة. |
| اليوم الثاني: 30 | 55 | 0 | التقرير اليومي وتقرير البونص وكشف الراتب والمالية تعرض 55. |
| إعادة إرسال اليوم الأول: 25 | 55 | 0 | لا عدّ مزدوج. |
| تصحيح اليوم الثاني إلى 35 | 60 | 0 | الفرق +5 فقط. |
| استيراد أداء اليوم الثاني بالقيمة 35 | 60 | 0 | تحديث نفس السجل لا إضافة سجل ثانٍ. |
| إضافة 440 | 500 | 1,800 | التارجت تحقق بدقة في جميع المستهلكات. |
| إضافة 50 | 550 | 2,050 | 1,800 + (50 × 5) في التطبيق والشركة والمشرف والتقارير والراتب. |
| إقفال الشهر | 550 | 2,050 | `PAYROLL_SNAPSHOT` تقرأ في تطبيق المندوب. |
| تعديل المصدر بعد الإقفال | المصدر قد يتغير | 2,050 | اللقطة المقفلة لم تتغير. |

## 8. حدود واضحة وقواعد أعمال غير مضافة

لم يضف هذا التسليم سياسة خصم حضور جديدة أو معدل غياب أو قاعدة إيراد تجاري. تظل تلك القرارات المؤسسية المطلوبة منفصلة عن قبول التزامن. كما أن الطلبات المؤهلة للإيراد في المسار الحالي تأتي من `DailyLog`، وهو سجل إدخال أو استيراد تشغيلي وليس إثبات تسليم خارجي مؤتمت.

تعذر فتح جلسة متصفح الرسومية داخل بيئة الاختبار المحلي؛ لذلك لم يُنفذ فحص بصري يدوي للشاشات. بدلاً من ذلك، فحصت مسارات API كاملة، وتركيب JavaScript، وسلوك `i18n.js` الديناميكي في وضع الإنجليزية. يجب تنفيذ مرور بصري قصير على النسخة التجريبية بعد التطبيق، خصوصاً تنزيل القالب وعرض أخطاء المعاينة.

## 9. أثر البيانات والنشر

لا توجد هجرة قاعدة بيانات في هذا التسليم، ولا حذف بيانات، ولا تعديل لسجلات إنتاجية. لا توجد إعادة ضبط قاعدة بيانات ولا نشر. يضيف التسليم اختبارات وتوثيقاً فقط إلى جانب التصحيحات المحدودة لخدمات الاستيراد، مخطط استجابة ملف المندوب، ومنع رفع مستند للمندوب الموقوف.
